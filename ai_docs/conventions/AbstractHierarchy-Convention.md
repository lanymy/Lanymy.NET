# Abstract Hierarchy Convention

本文档用于沉淀 `Lanymy.NET` 全仓范围内“抽象基类 - 中间抽象层 - 具体实现类”的继承约定。

## 1. 适用范围

- 本规则对 `Lanymy.NET` 整个项目生效。
- 适用于仓库内所有存在模板方法、生命周期方法、释放钩子或“抽象层 + 实现层”结构的继承体系。
- 典型场景包括：
  - `WorkTask`
  - `Socket`
  - `CMD`
  - 其他机制型模块

## 2. 核心规则

- 若某个模板方法或生命周期方法已经在最上层抽象基类中声明为 `abstract`，中间抽象层默认不再重复声明同一个成员。
- 中间抽象层只有在“需要改变签名约束、可见性表达、泛型约束或补充新的抽象语义”时，才应重新声明该成员。
- 若没有新增语义，只是为了“提醒具体类实现”，则不应在中间抽象层重复写一遍相同的 `abstract` 成员。
- 该规则默认作为仓库级编码约定处理，不限于某一个模块专题。

## 3. 设计目的

- 让抽象约束的来源保持单一，避免维护者在多层抽象中追踪同一条规则。
- 避免中间抽象层出现“看似加强约束，实际只是重复声明”的冗余代码。
- 让具体实现类清楚知道：它实现的是顶层基类定义的契约，而不是某个中间层临时重复出来的同名约束。

## 4. 与空实现的边界

- 若顶层基类把某个方法定义为 `abstract`，中间抽象层不应通过空实现把它“降级”为默认可继承逻辑。
- 只有当仓库明确决定“提供默认行为”时，才允许把抽象方法变成虚方法或提供具体实现。
- 如果中间层只是为了占位而返回 `Task.CompletedTask`、空集合或空分支，应先确认这不会削弱原本的编译期约束。

## 5. `WorkTask` 当前约定

- `BaseWorkTask` 负责定义 `OnStartAsync()`、`OnStopAsync()`、`OnDisposeAsync()` 这组生命周期契约。
- `BaseSimpleWorkTask`、`BaseSimpleWorkTaskQueue` 作为中间抽象层，不再重复声明 `OnDisposeAsync()`。
- `SimpleWorkTask`、`SimpleWorkTaskQueue` 等真正 concrete class 需要显式实现 `OnDisposeAsync()`。

## 6. 修改建议

1. 先确认抽象约束最早定义在哪一层。
2. 再判断中间抽象层是否真的增加了新的语义。
3. 若没有新增语义，优先删除重复的抽象声明，而不是继续堆叠。
4. 若需要默认行为，应在文档中明确说明“这是设计放宽，不再是强制实现”。
